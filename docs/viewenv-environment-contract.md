# ViewEnv Environment Domain (V1 scoped implementation)

The canonical runner is **`neoweaver.native.run_native_arm`**; independent
Oracle consumption remains **`inspect_native_pair`**. They are not recreated
in ViewEnv. This domain is a single per-instance, owner-fixed episode and
an actual source-bound parser consumer, with one admitted Harness candidate
action, one termination, and an optional original NativePairReport attachment.

- `ViewEnvEpisode.propose_patch`: native `parse_proposal` consumes the
  same Owner-provided fixed refs and three bounded surfaces.
- `ViewEnvEpisode.attach_native_pair`: only original `NativePairReport`;
  the ref/snapshot matches and original effect/authority ceiling remain.
- `ViewEnvEpisode.terminate`: never produces scalar reward, oracle PASS,
  training eligibility, or landing permission.
- OpenEnv `make_environment_class(spec)`: authentic MCPEnvironment and
  FastMCP tool API, one bounded episode per instance, no generated ID.
  `make_private_app` remains uncalled until an authorized private Host
  selects the exact fixed inputs. It cannot be exposed on the public UI.
- Verifiers `make_tool_env(spec, dataset, independent_rubric)`:
  authentic `vf.ToolEnv`, no default dataset, scorer or hidden oracle.
  The `ViewEnvToolkit` is independently testable without the optional
  dependency. The external rubric is its own Verification Owner.

**Important limitation:** this is a runnable environment *interface* and
negative/positive parser controls, but a real model-driven OpenEnv or
Verifiers rollout remains NOT_RUN until installed provider/runtime and an
approved isolated original task are available. H0/H0 transport and H0/H1
improvement are separately verified by original Native Owners. Placeholder
scores must remain null/UNKNOWN, never `0.0`.

Future ORS and NeMo Gym adapters shall wrap this same domain model:
ORS may expose original per-step evidence, but NEVER synthesize reward;
NeMo Gym's verify handler must fetch an independent original verification
record, never infer from a termination string. No second lifecycle ledger.

Harness² is an optional, explicitly authorized edit policy.
`Propose → Probe → Compose` emits original bounded proposal data, consumes
Noodle-controlled probes, and may suggest owner-reviewed transfer artifacts;
the proposal cannot use default unrestricted network or disabled sandbox.
First comparison: baseline H0/H0, then an observed Soodles decision failure
with isolated H0/H1, same frozen solver/task/budget/seed policy.
